# Review: 1KCP-informed Minigraph-Cactus plan for Snellius

This reviews `MINIGRAPH_CACTUS_1KCP_HPC_PLAN_DRAFT.md` against `whole_pans/AGENTS.md`, the existing one-shot implementation, the [1KCP paper](https://www.nature.com/articles/s41586-026-10315-y), its [analysis repository](https://github.com/JianYang-Lab/1KCP-analysis), and pinned [Cactus v3.3.0 documentation](https://github.com/ComparativeGenomicsToolkit/cactus/blob/v3.3.0/doc/pangenome.md) and source. No local tests, Snakemake runs, dry runs, or path resolution were performed.

## P0: correct before writing the staged workflow

1. **Make the five Cactus calls match the pinned version's actual contract.** The draft's topology is right: `cactus-minigraph` (whole-genome GFA), `cactus-graphmap` (PAF plus graph FASTA), `cactus-graphmap-split` (chromfile and subproblems), `cactus-align --batch` (one HAL and raw VG per listed chromosome), then `cactus-graphmap-join`. `cactus-graphmap` must be given `--outputFasta` because the initial seqfile has no `_MINIGRAPH_` event. **Before standalone split, create a second deterministic seqfile with `_MINIGRAPH_ <graph FASTA>` added**; split explicitly rejects a seqfile without that synthetic leaf. Feed the split-produced `chromfile.txt` directly to batch align; its rows have **three** fields (chromosome, seqfile, PAF). Derive the ordered chromosome names from that file, reject duplicate/empty rows and missing outputs, and pass the exact `<chrom>.raw.vg` and matching `<chrom>.hal` files to join as separate argument-vector lists. Join accepts `.raw.vg` paths and strips `.raw` internally; a guessed `<chrom>.vg` path will fail. [v3.3.0 graphmap parser](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap.py), [split chromfile writer](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap_split.py), [join parser](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap_join.py).

2. **Resolve final provenance outputs explicitly.** Standalone join's `--sv-gfa` is for a *per-chromosome* Minigraph batch: its source requires the same number of `.gfa.gz` entries as `--vg` entries. Do **not** pass the one whole-genome Minigraph GFA to `--sv-gfa` alongside ~25 VGs. Keep the Minigraph stage GFA as its own retained artifact and, if the final output contract must include `<outName>.sv.gfa.gz`, make an identity-preserving copy/link with recorded hash; do not claim join made it. `--hal` needs exactly one file per VG to produce the merged `.full.hal`. The draft promises `<outName>.input-contig-sizes.tsv.gz` and `clipped-by-genome.tsv`, but standalone join only produces the clipping/exclusion report when given `--inputContigSizes`. The split stage's `contig_sizes.tsv` is a different format and is rejected. Extend the streaming preflight to record lengths and emit Cactus's five-column sanitized-name baseline (`#event`, `pansn_prefix`, `base_contig`, `offset`, `length`), or make exclusion reporting an explicitly deferred feature with a smaller output contract. Even with this baseline, standalone join receives no split log, so it labels sequence missing from all graph phases as unaligned rather than distinguishing ambiguous versus unassigned contigs; retain the split log and report those causes separately. Validate baseline naming against a server pilot before interpreting lost-base fractions. [join source and length checks](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap_join.py), [baseline format and split-log limitation](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/pangenome_exclusions.py).

3. **Update the output list for v3.3.0.** The current `minigraph_cactus_common.py` requires `.d2.min`; pinned join source creates `.d2.shortread.withzip.min` and `.d2.shortread.zipcodes` (plus `.d2.dist` and `.d2.gbz`) for `--giraffe`. Its documentation's older `.d2.min` example is stale. Make the required list follow the pinned implementation, and still confirm actual filenames from the server pilot. The graph's ordinary GFA/GBZ are clipped; the `.d2` indexes are frequency filtered. [v3.3.0 index writer](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap_join.py).

4. **Remove the unverified `--validate` inheritance from the one-shot wrapper.** The pinned `cactus-pangenome` parser is composed of `pangenome_options` and `graphmap_join_options`; neither defines `--validate`. Thus the current wrapper's `--validate` is likely an immediate CLI error, despite later `master` docs describing that option. Do not propagate it to new stages. Ask `cactus-pangenome --help` and `cactus-align --help` **on the server** before deciding whether alignment validation can be requested as a stage option; if absent, document a separate supported HAL/graph check after the build. [v3.3.0 pangenome parser](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_pangenome.py), [v3.3.0 join options](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap_join.py).

5. **Treat each stage as an immutable, independently restartable Toil workflow.** Use a unique `<jobstore_root>/<build_id>/<stage>` and a distinct stage state/marker, not the old one-shot store. A marker is published only after process exit zero and checks of that stage's named outputs. Failed stores and partial directories are retained. `--restart` is allowed only with matching input/settings fingerprint plus a recorded unfinished workflow in that stage's store; a completed command with exit-zero state can be adopted after output inspection if marker publication was interrupted. Do not decide success from file existence, and do not reuse the same store for the next Cactus command. Protect against concurrent launch of the same build/stage. `--clean=onSuccess` can remove the store before marker publication, so the completed/adopt branch matters. A new stage layout requires a new build ID and cannot adopt the existing one-shot output. [Toil cleanup/restart options](https://toil.readthedocs.io/en/releases-9.0.0/running/cliOptions.html).

## P1: HPC and scientific corrections

6. **Keep node reservations within Snellius's stated shapes.** The current one-shot `driver_mem_mb: 524288` cannot fit the 336 GB small node; it must be replaced for the staged rules. The draft's 288 GB small-node and 1,300 GB fat-node aggregate reservations are reasonable starting requests, not measured needs. Snakemake `threads` and `mem_mb` must cover *all concurrent Toil jobs* in `single_machine`; Toil `--maxCores` and `--maxMemory` constrain that aggregate. Verify `--maxDisk` against actual local scratch, because it is a scheduling limit, not preallocated space. For scheduler-backed Toil, distinguish the leader's Snakemake reservation from Toil worker requests, cap `--maxJobs` or equivalent concurrency to site policy, and specify worker partition/time/log options in server config/profile. Do not request a full fat node for a leader while also submitting fat workers unless intentional. [Cactus HPRC scale example](https://github.com/ComparativeGenomicsToolkit/cactus/blob/v3.3.0/doc/pangenome.md#hprc-graph-running-all-at-once), [Toil resource options](https://toil.readthedocs.io/en/releases-9.0.0/running/cliOptions.html).

7. **Prefer node-local scratch without persisting a leader-specific path.** `work_dir` currently points to GPFS. Let Toil inherit a node-local `TMPDIR` in a one-node allocation when the server confirms capacity; if using `--workDir`, make it a per-worker local path valid on every assigned node. Keep job stores, results and logs on shared GPFS; use a shared `--batchLogsDir` in scheduler mode. Confirm environment propagation and free space/inode quota on the server. A path such as `$TMPDIR` must not be frozen into the graph fingerprint as a different filesystem location on each node. [Toil work/batch logs options](https://toil.readthedocs.io/en/releases-9.0.0/running/cliOptions.html).

8. **Keep the biological comparison honest and the join feasible.** The final 1KCP 2,232-haplotype graph uses Minigraph, gaffilter, ODGI subgraphs, seqwish, smoothxg, GFAffix and read-supported filtering; its earlier 45-diploid Minigraph-Cactus graph has a separate PIGA role. This workflow is a Minigraph-Cactus graph for the selected cleaned haplotypes, not a reproduction of the final 1KCP graph. Chromosome splitting drops ambiguous and interchromosomal mappings; report their bases and distinguish that from join clipping. The 2–3-haplotype pilot checks syntax, while a 12–20-haplotype pilot gives only a scaling estimate; neither proves that full-cohort join/indexing fits 1,440 GB. Record peak memory, scratch, GPFS space and walltime at each stage and adjust requests only from those data. [1KCP paper](https://www.nature.com/articles/s41586-026-10315-y), [1KCP repository](https://github.com/JianYang-Lab/1KCP-analysis), [Cactus split behavior](https://github.com/ComparativeGenomicsToolkit/cactus/blob/v3.3.0/doc/pangenome.md#pipeline).

9. **Keep reference and input behavior aligned with the implementation.** CHM13 is the first, intact backbone; GRCh38 is second reference-sense path and lacks chrM in the configured input. Pass `--reference CHM13 GRCh38` where supported; pinned graphmap and split parsers silently reduce it to the first reference, while Minigraph and join retain both. Do not interpret their second-reference omission as a missing graph path. An explicit `--refContigsFile` generated from CHM13's server preflight may be clearer than a long command line, but use it only if it preserves the intended chr1–22, chrX, chrY, chrM set and decide how any additional CHM13 contigs are treated. Preflight should record per-contig base lengths and reject Cactus-effective name collisions. The inclusion list remains authoritative, including surviving single haplotypes from `PARTIAL` samples. [v3.3.0 reference docs](https://github.com/ComparativeGenomicsToolkit/cactus/blob/v3.3.0/doc/pangenome.md#reference-sample), [split parser](https://raw.githubusercontent.com/ComparativeGenomicsToolkit/cactus/v3.3.0/src/cactus/refmap/cactus_graphmap_split.py).

10. **Keep the Snakemake layer modest.** One explicit target excluded from `rule all`, five sequential stage markers plus preflight, and a no-output verifier are enough. Each real stage gets `threads`, `resources`, `log`, `benchmark`, and the existing pinned Conda environment. Use an argv list in a small launcher so `--vg` and `--hal` lists are passed without globs or shell substitution. Fingerprint content-affecting settings and installed Cactus version as well as input hashes. Record resources and command vectors per stage. Resource changes may need a fresh Toil store or a deliberately supported retry policy; do not silently mutate a running stage's request. Preserve the SV-only graph rules and prior one-shot artifacts.

## Decisions the implementer can make now

- Implement the ordinary whole-genome Minigraph route with chromosome split and batch alignment; leave `--mgSplit`, `--collapse`, `--noSplit`, `--permissiveContigFilter`, `--haplo`, and 1KCP's ODGI/seqwish route as separately named experiments.
- Use CHM13 as first reference, GRCh38 as second, CHM13-only VCF, default clipping/filter threshold and the pinned v3.3.0 output filenames. Preserve original inputs and the SV-only graph.
- Choose a new staged build ID; keep each stage's shared outputs and store namespace isolated. The existing one-shot run cannot be resumed as a staged job.
