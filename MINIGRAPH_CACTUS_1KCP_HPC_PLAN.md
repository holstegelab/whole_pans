# Reviewed Minigraph-Cactus plan for Snellius

The [1KCP paper](https://www.nature.com/articles/s41586-026-10315-y) built its final 2,232-haplotype graph with Minigraph, chromosome-scale subgraphs, seqwish, smoothxg, GFAffix and read-supported filtering. Its earlier 45-diploid PIGA graph used Minigraph-Cactus. This project builds a **Minigraph-Cactus** graph from the post-decontamination inclusion list, CHM13 and GRCh38; it borrows scale and QC lessons from 1KCP without claiming to reproduce its final graph.

## Workflow

Use the [Cactus v3.3.0 stepwise interface](https://github.com/ComparativeGenomicsToolkit/cactus/blob/v3.3.0/doc/pangenome.md): preflight; whole-genome `cactus-minigraph`; `cactus-graphmap` with `--outputFasta`; `cactus-graphmap-split` with the seqfile that graphmap augments with `_MINIGRAPH_`; `cactus-align --batch --pangenome --outVG`; and `cactus-graphmap-join` with the chromfile-ordered `.raw.vg` and matching `.hal` inputs. Graphmap mutates its input seqfile in v3.3.0, so it receives an exact private copy of the frozen preflight seqfile. Verify the Cactus-added graph leaf, path and unchanged original sample map before publishing an augmented copy for split. Keep CHM13 first and GRCh38 second. Pass both as references where the CLI accepts them, and produce the CHM13 VCF. Cactus chooses its own non-reference Minigraph insertion order; the seqfile order does not imitate 1KCP's Mash order.

Each stage has a separate shared Toil store, state file, lock, log, Snakemake benchmark and success marker. Stage products are retained. Markers record size and modification time for all named products and SHA-256 for small control files; split's marker includes its assignment log, contig-size table and each chromfile-referenced seqfile/PAF. Restart only a matching unfinished store; adopt a stage that logged exit zero but lost marker publication only after inspecting its outputs. Never overwrite the earlier one-shot build: use the new `build_id` in config. The SV-only workflow remains independent.

Standalone join cannot take the single whole-genome Minigraph GFA as `--sv-gfa` beside chromosome VGs. Retain that GFA in `stages/minigraph/` and record it as the SV graph artifact. The staged join produces clipped GFA/GBZ, raw and normalized CHM13 VCFs, full HAL and the v3.3.0 `.d2` Giraffe indexes. `--validate` is absent from the pinned CLI and is omitted. The five-column `--inputContigSizes` baseline and join's `clipped-by-genome.tsv` are **deferred** pending a server pilot of Cactus-sanitized naming; the preflight contig map includes lengths and the split directory/log are retained for separate lost-base analysis. No clipping-loss percentages should be inferred from the graph alone.

## Snellius baseline

Use single-machine Toil inside a Snakemake allocation: Minigraph, mapping and split on a 192-core/336-GB small node; alignment and join on a 192-core/1,440-GB fat node. Initial rule reservations and Toil caps are in `config/config.yaml`. They are estimates, not measured peaks. Let Toil inherit node-local `TMPDIR` only after checking its capacity on the server; keep stores, logs and results on GPFS. Do not submit separate Toil workers from a full-node Snakemake leader. A scheduler-backed mode is deferred until partition names, walltime, worker environment propagation and quotas are confirmed on Snellius.

Run a separate 2–3-haplotype CLI smoke pilot, then a 12–20-haplotype representative pilot, each with its own build ID and stores. Check stage peaks for RAM, scratch, GPFS space and walltime, plus `.WARNING`, chromosome assignment and ambiguous contigs, reference paths, VCF/index readability and final graph statistics. A small pilot cannot prove the full-cohort join fits. No local execution or validation is permitted by `whole_pans/AGENTS.md`.
